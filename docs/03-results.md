## Independent critic

### Round 1

A fresh agent was given the frozen candidate and the acceptance criteria, but not the builder's reasoning. It found **no critical failure**, and independently confirmed:
- the goldens are byte-identical when regenerated from upstream
- profile on/off behaves as claimed
- every boundary escape it tried was denied
- modified upstream tests were changed only as much as the behavior change required
- AGPL license and attribution are untouched

It confirmed six defects, **all fixed** in `f9f76ff`:

| # | Finding | Fix |
|---|---|---|
| 1 | SVG figures could read local images by absolute path (upstream code path, outside the boundary) | `stripExternalRefs` + CSP on the fallback page; end-to-end pixel test |
| 2 | Checker false positives ("stopping power", "need to go over", "excellent resolution", URL + full stop) and false negatives (prose question stacks, "great job", colon-less MRN, patient advice); steers split turns | Patterns rewritten; 6 regression tests; unknown guideline IDs listed for a hand check |
| 3 | `profile.ts` silently replaced a malformed `settings.json` | Refuses, changes nothing; test |
| 4 | Prober not covered on the real request path | Scenario S0b |
| 5 | Three profile clauses pulled against practice doctrine | Explicit practice deferrals; tests pin them |
| 6 | Boundary created the study folder on every call | Removed; test |

Not fixed: `ls` shows whether a symlink's target is a directory. This leaks one bit, never contents.

### Round 2

A fresh critic attacked only the round-1 repair. **Confirmed and fixed in `70c342a`:**

| Finding | Fix |
|---|---|
| **High:** the SVG stripper missed other namespace prefixes (`foo:href` bound to XLink) and paths containing an apostrophe; resvg read the file | Any-prefix `*href` matcher with a correct quoted/unquoted value grammar; DOCTYPE and `<meta>` removed; end-to-end pixel tests for each vector |
| **Medium:** checker false positives ("have to run the numbers", "leave a margin", "good question to ask of any dose calc", "patient-specific QA", "MRN 4000") and false negatives ("let's wrap up", "Great —", "Very good.", "MRN-1234567", "DOB: March 4 1961", "Mr. Smith") | Sentence-shaped stop and praise patterns; real identifier shapes; 4 regression tests covering every case the critic listed |
| **Low:** `profile.ts` rewrote odd-but-valid fields through the app's sanitizer | It edits only its own key in the raw JSON; test |
| **Low:** the browser fallback is easy to reach (SVG without `xmlns`) | Same sanitizer runs before both paths; the CSP stays as a second layer |

The critic confirmed these held: the study-folder boundary (missing root, symlinked root, dangling root), write ordering in `profile.ts`, practice deferral in the profile text, and the legitimate figures (`data:` images, `#id` references).

**The checker is a screen, not a judge.** It now passes every realistic sentence the critics produced, but it's built on patterns. Read its findings before logging them in `results.csv`.

### Round 3 (the last of 3 allowed)

A fresh critic was aimed only at the SVG stripper, the one regex-based security control. It found **no leak on the resvg path**. It also confirmed the control is load-bearing: with the stripper bypassed, resvg reads local files through `<image>` and `<feImage>`.

These held:
- xlink and uppercase hrefs, tab or newline before the attribute
- `<a>`, nested `<svg>`, `<feImage>`, `<pattern>`, external `<use>`
- duplicate attributes, xml:base, entities without DOCTYPE, CDATA
- CSS `@import` and `url()` (resvg fetches neither)

Valid figures still render.

One theoretical gap was noted: a lenient HTML-mode parse on the browser fallback would accept an href glued to the previous attribute's quote (`x="0"href="…"`), although the fallback's CSP would still block the fetch. That was closed anyway in the round-3 commit, with a test.

The repair budget is spent and acceptance passes, so the review stops here.

## Known limitations

- **The problem's committed solution is in the browser payload** (upstream design): the practice UI never renders it before conclude (upstream test `render-practice-surface`), but it's visible in DevTools. Fixing that would change upstream's view contract, so it's out of scope for a 5% fork.
- **The reference video couldn't be reached** from this environment (YouTube blocked by the proxy, no transcript found). The build rests on the repository alone.
- **The cost meter in the screenshots** (e.g. "$0.0023") is upstream's estimate for the configured model ID applied to scripted turns. No API call was made.
- **Files dropped into a message from outside the study folder are refused.** 0.4.1 lets you drag a file into the composer as a path chip. The agent can only open it if it's inside the study folder, and otherwise tells you where the folder is.
- **The study folder defaults to `<data dir>/study`.** In the desktop app that's inside the app's data directory, so set `LH_STUDY_DIR` to a folder you use.
